= List continuation サンプル
:toc:
:icons: font

list continuation は、リスト項目にパラグラフ・コードブロック・表などのブロックを「アタッチ」する機能です。
単独行の `+` を、アタッチするブロックの直前に置きます。
このファイルは、公式ドキュメントの説明に沿って、典型的な使い方をまとめたサンプルです。

== 1. パラグラフをアタッチする

順序付きリストの項目に、追加のパラグラフを付けます。
`+` がない場合、空行を挟んだパラグラフは別のブロックとして扱われ、リストが途切れてしまいます。

. 設定ファイルを用意します。
+
このパラグラフは、1番目の項目に属しています。
空行ではなく `+` で接続しているため、リストは途切れません。
+
さらにパラグラフを続けることもできます。
`+` を置くたびに、同じ項目へ連鎖してアタッチされます。

. アプリケーションを起動します。
+
2番目の項目にも、パラグラフを付けられます。
採番は 1, 2, 3 と連続します。

. 動作を確認します。

== 2. パラグラフとコードブロックを混在させる

パラグラフ、コードブロック、パラグラフの順に連鎖させる例です。
各ブロックの前に `+` を置きます。

. 設定ファイルを作成します。
+
次のような内容で `config.yml` を保存します。
+
[source,yaml]
----
server:
  port: 8080
----
+
ポート番号は、環境に合わせて変更してください。

. アプリケーションを起動します。
+
[source,bash]
----
./run.sh
----
+
起動後、ログに待ち受けポートが表示されます。

. ブラウザで動作を確認します。

== 3. 表をアタッチして採番を維持する

Qiita記事で紹介されている、表を挟んでも採番が崩れない例です。

. foo
+
|===
||0|1

|0|0|1
|1|1|0
|===

. bar

. baz

== 4. open block でまとめる（公式推奨）

複数のブロックを付ける場合は、open block（`--`）で包むと、`+` が1つで済みます。
open block の中では、通常の文書と同じように、空行を入れながら書けます。

. 設定ファイルを作成します。
+
--
次のような内容で `config.yml` を保存します。

[source,yaml]
----
server:
  port: 8080
----

NOTE: ポート番号は、環境に合わせて変更してください。

|===
|キー |説明

|port
|待ち受けポート
|===

最後に、保存した内容を確認します。
--

. アプリケーションを起動します。

. 動作を確認します。

== 5. 行末の `+` との違い

行末の `+` は list continuation ではなく、強制改行です。

* 行末の `+` の例です。 +
この行は、直前の行の続きとして改行されます。
+
単独行の `+` の後に書いたこのパラグラフは、この項目にアタッチされます。

* 次の項目です。

== 6. ネストしたリストでの使い方

ネストした項目に付けたブロックは、直前の項目（ここでは 1-1）に属します。

. 手順1
.. 手順1-1
+
この説明パラグラフは、手順1-1に属します。
+
[source,bash]
----
echo "1-1"
----
.. 手順1-2
. 手順2

親項目（手順1）へアタッチする ancestor list continuation は、公式が壊れやすい構文と注意しています。
複雑になる場合は、親項目の側で open block にまとめる構成のほうが安全です。

== 7. よくある失敗

次のように `+` を忘れると、採番が1に戻ります。

----
. foo

段落

. bar
----

上の例では、`段落` がリストを途切れさせるため、`bar` が新しいリストの1番目になります。
`[start=2]` で番号を直す方法は、公式が推奨していません。
項目の追加のたびに手作業での調整が必要になり、根本の原因も解決しないためです。
